## 1. 项目概述

车路通 DSSAD 产品云平台面向低速自动驾驶运营企业，提供：

1. **车辆数据接入**：接收车端经 MQTT 上报的运行状态、故障、事故、轨迹等数据；
2. **运营管理**：Web 控制台（车辆、事件、远驾、地图阻断、视频取证、链路监控）；
3. **监管合规**：按《平台数据对接接口文档 v1.0.0》向准入监管平台开放云云 HTTP 接口；
4. **事故取证闭环**：事故发生后联动下发取证请求、接收四方向视频归档、待归档催办。

## 2. 术语

| 术语 | 定义 |
|---|---|
| DSSAD | 自动驾驶数据存储系统（车端记录装置），本文指其云端延伸 |
| 云云对接 | 企业云端 ↔ 监管平台的 MQTT（车云）/ HTTP+HMAC（云云）通道 |
| 待归档事故 | 已请求取证但尚未收到全部媒体文件的挂起事故 |
| 严重故障 | severity ≥ 6 的故障（与后端 `faultSevereToday` 口径一致，前端不得另立阈值） |

## 3. 用户角色

| 角色 | 入口 | 关键操作 |
|---|---|---|
| 平台运营人员 | Web 控制台（X-Token 登录） | 全部管理功能 |
| 监管平台 | 服务对服务（HMAC 签名） | 云云 HTTP 接口调用 |
| 车端 | MQTT 通道（车云/企业网关） | 状态/故障/事故/轨迹上报 |
| 交巡警/远驾舱 | 经监管平台或控制台 | 发起/结束远程接管 |

> 权限模型现状：单一角色（缺陷 P-08 已登记），RBAC 列入路线图。

## 4. 业务用例

### UC-01 车辆接入与实时监控
运营人员登录控制台 → 总览查看在线率/今日事故/待取证 → 车辆列表检索车辆 →
详情页查看实时状态、轨迹回放、历史视频。

### UC-02 事故取证闭环
车端上报事故 → 平台经 MQTT 下发取证请求 → 车端四方向视频经 `/manager` 回传归档 →
事件中心「待归档事故」卡片计数，超 10 分钟未收到取证自动进入催办清单。

### UC-03 远程驾驶接管
交巡警/监管平台发起接管 → 平台 LRU 分配远驾舱与驾驶员 → 同步上报监管平台 →
结束接管自动配对（P-04 防御：新发起自动闭合悬挂旧记录；结束早于发起按孤儿落库）。

### UC-04 地图阻断同步
监管平台推送/平台定时拉取（00:05，分布式锁 P-01）当日阻断设施 → 平面图渲染 →
下发车辆生效。

### UC-05 链路自证
运维通过链路监控页查看 MQTT 通道状态、入站队列/丢弃、离线补传队列、限流触发次数，
配合 `mqtt-watch.sh`（退出码分级）实现「探活全绿 ≠ 收得到数据」的通道级验证。

## 5. 功能需求

| 编号 | 需求 | 验收口径 | 状态 |
|---|---|---|---|
| FR-01 | 车辆实时状态/位置/轨迹接入 | 心跳与状态上报后 3s 内控制台可见 | ✅ |
| FR-02 | 车辆在线状态自动回落 | 心跳超时后由扫线任务置离线（P-02） | ✅ |
| FR-03 | 故障/事件分页检索 | 按时间/VIN/类型组合筛选，分页上限受控 | ✅ |
| FR-04 | 事故取证请求下发与媒体归档 | 取证链路全环节数据库留痕 | ✅ |
| FR-05 | 待归档事故催办清单 | 超 10 分钟未取证进入催办列表 | ✅ |
| FR-06 | 远驾接管发起/结束与台账 | 见 UC-03 与 P-04 防御语义 | ✅ |
| FR-07 | 地图阻断推送+定时拉取兜底 | 拉取幂等落库，多实例单实例出网 | ✅ |
| FR-08 | 云云 HTTP 接口（HMAC） | 与上游 PDF 逐条对齐，偏差留痕 | ✅ |
| FR-09 | 报文留痕与采样 | full/sampled/event-only 三档可配 | ✅ |
| FR-10 | 管理接口限流（HTTP 100 次/分·车） | 超限返回限流响应，监控页可见触发计数 | ✅ |
| FR-11 | 下行 MQTT 发布限流 | 被拒不丢弃、转离线队列缓发 | ✅ |
| FR-12 | 遥测数据生命周期清理 | 轨迹/状态流水按保留天数清理，0=不清理 | ✅ |
| FR-13 | 登录鉴权与登出真失效 | 登出后旧 X-Token 服务端吊销 | ✅ |
| FR-14 | RBAC 角色权限 | 高危操作（模拟器/远驾接管）按角色收敛 | 📋 P-08 |
| FR-15 | 接管单号级配对 | 平台生成接管单号并要求车端回带 | 📋 待上游支持 |

## 6. 非功能需求

| 编号 | 类别 | 需求 | 实测/现状 |
|---|---|---|---|
| NFR-01 | 性能 | 只读接口 P95 达标（1000 台车规模） | 见《性能优化与压测报告》DS-1/DS-2 |
| NFR-02 | 性能 | 缓存二级化（Caffeine L1 + Redis L2） | DS-2 对照实验有收益数据 |
| NFR-03 | 容量 | 遥测流水按预算保留 | 单行 178B，1000 台车 14.3GB/天反推 |
| NFR-04 | 可用性 | MQTT 断连不丢下行指令 | 离线队列 + 补传（限 20 条/秒摊平突发） |
| NFR-05 | 安全 | X-Token 不允许明文传输 | 生产强制 HTTPS（TLS 1.2+） |
| NFR-06 | 安全 | `/actuator/**` 双层收敛 | Nginx 404 + 来源 IP 白名单 fail-closed |
| NFR-07 | 可观测 | 通道级探活（退出码分级告警） | `mqtt-watch.sh` 退出码 0/10/20/30/40/90 |
| NFR-08 | 可测试 | 行覆盖门槛 0.60 绑定 verify | 227+ 用例，构建不达标即失败 |
| NFR-09 | 可部署 | 零外部依赖本地起服 | local profile：H2 文件库 + 模拟器 |
| NFR-10 | 前端体验 | 首屏弱网不黑屏 | index.html 内联骨架屏；Nginx gzip 静态资源 |

## 7. 验收基线

1. `mvn verify` 全绿（用例数见《测试说明》），覆盖率门槛通过；
2. `npm run type-check` + `npm run build` 零错误；
3. `bash scripts/health.sh` 14 条断言全通过（含鉴权与登出失效）;
4. `bash scripts/mqtt-watch.sh --allow-disabled` 退出码 0；
5. 生产态：`run-local.sh --prod` 起服后 `ddl-auto=validate` 通过（实体与 MySQL 一致）。

## 8. 范围外（明确不做）

- 第三方地图底图接入（阻断区域本身即闭合多边形，叠加底图引入合规与加载失败风险）；
- 乘用车 C 端功能（本产品只面向运营侧 B 端）；
- 监管平台侧自身的功能演进（由监管方负责）。
